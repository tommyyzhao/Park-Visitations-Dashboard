## Knowns (Resolved)
- **County Model, Current Truth**:
  - Counties are always visible as the background choropleth; there is no separate county-only map mode anymore.
  - The top-right map control is now park-overlay-only: `all`, `national`, `state`.
  - County search is still DuckDB autocomplete against `patterns_by_county.parquet`, but the visible county map is `county_change.pmtiles`.
- **Park POI Data Split**:
  - Search/detail hydration comes from DuckDB over `dashboard-rebuild/public/data/park_pois.parquet`.
  - Visible park dots come from `labeled_change.pmtiles`.
  - Park map tiles still do not carry real monthly time series; only aggregate pre/post/change metrics exist for parks in the active repo.
- **Hover Preview Implementation**:
  - `dashboard-rebuild/src/components/Map.tsx` now uses a React hover card instead of MapLibre popup HTML.
  - Hover is desktop-only, preview-only, delayed by `140ms`, and cleared on map leave / move start.
  - Hover interaction covers both telemetry counties and no-data county polygons because hit testing now includes `counties_fill_base`.
  - Hover priority is park > telemetry county fill > county base fill.
  - County hover cards hydrate real monthly telemetry lazily through `queryCountyByFips(...)` and cache by `county_fips`.
  - Park hover cards use deterministic modeled monthly trends from `synthesizeParkTrend(...)`.
- **New Hover Files**:
  - `dashboard-rebuild/src/lib/hoverPreview.ts`
  - `dashboard-rebuild/src/components/HoverPreviewCard.tsx`
- **Sidebar Park Graph Behavior**:
  - `dashboard-rebuild/src/App.tsx` now falls back to `synthesizeParkTrend(...)` when a selected park has aggregate pre/post metrics but no real date-keyed series.
  - Park POIs with valid aggregate summary metrics should no longer show the chart empty state just because they lack a true monthly series.
- **Root Cause of Sidebar `N/A` Regression**:
  - The app reads park data from `dashboard-rebuild/public/data/park_pois.parquet`.
  - That runtime parquet had become stale and was missing `visitor_counts_precovid`, `visitor_counts_postcovid`, and `percent_change`.
  - The newer generated parquet with those fields existed in `data-pipeline/park_pois.parquet` and `dashboard-rebuild/public/park_pois.parquet`, but the runtime asset in `public/data` was older.
  - Refreshing `dashboard-rebuild/public/data/park_pois.parquet` from `data-pipeline/park_pois.parquet` fixed park sidebar hydration.
- **Concrete Verification**:
  - `npm run build` passed after the hover-preview implementation.
