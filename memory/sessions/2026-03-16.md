# Session Log: 2026-03-16

## Objectives
- Rebuild county visualization from point markers into proper polygon counties.
- Then revise the UX so counties stay always visible in the background while park POIs render on top.

## Knowns (Resolved)
- **Vite optimization**: Large library binaries (1.7MB+) causing Rollup warnings were mitigated using `rollupOptions.manualChunks` and `React.lazy()` bundling strategies.
- **Map Telemetry Gap**: Resolved the disconnect between shallow PMTiles feature properties and full Parquet telemetry records. Map clicks now trigger an id-based DuckDB lookup to hydrate charts.
- **County Data Keys**: Verified that `county_fips` is the most reliable join key for county-level telemetry lookups in the `patterns_by_county.parquet` dataset.
- **County Boundary Vintage**: The county choropleth build must use the 2018 Census generalized county boundaries, not 2024, because the telemetry still uses legacy county-equivalent FIPS. The 2024 join failed on Connecticut + Alaska IDs; 2018 matched all 3,142 telemetry counties.
- **County Tile Builder**: There is now a repeatable builder at `data-pipeline/build_county_tiles.mjs` plus a `build:county-tiles` script in `data-pipeline/package.json`. It downloads Census boundaries, joins telemetry, computes pre/post-COVID metrics, fails on unmatched telemetry FIPS, and emits `data-pipeline/county_change.pmtiles` plus `dashboard-rebuild/public/data/county_change.pmtiles`.
- **Active Map UX**: The rebuilt app no longer has a county-only map mode. Counties are always rendered in the background, the map buttons are park-only filters (`All`, `National`, `State`), county search/click outlines the county without changing the park overlay, and county clicks still hydrate the sidebar through DuckDB by `county_fips`.
- **County Visual Stack**: County polygons are rendered with a muted base fill, translucent choropleth fill, subtle blurred glow halo, crisp outline, and selected-county outline.
- **Park Visual Stack**: Park POI circles were explicitly kept on the percent-change color ramp, not changed to blue, and set to high opacity with a dark stroke so they read as the foreground layer.
- **Overlay Click Precedence**: Overlapping map interactions now resolve through a single `queryRenderedFeatures()` path so parks win over counties when both are under the cursor.
- **Layering Intent**: After user feedback, `Map.tsx` was adjusted again so counties should render beneath park dots rather than above them.
- **Runtime Verification**: `npm run build` passed after each major map-state revision, and browser smoke tests verified that county search still hydrates Los Angeles, counties render by default, the county button is gone, and the console is warning-free. The final layer-order/ramp fix was build-verified, but not yet given a fresh dense-city visual QA pass.
